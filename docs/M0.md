# M0：地基

目標：把專案骨架、資料庫、排程框架、資料源轉接層、登入與資料狀態頁建好，讓後續里程碑（M1 起）只需要加資料與功能，不必再動地基。M0 不抓任何真實市場資料。

## 開工前，請先向使用者確認的事

下列帳號與資源由使用者準備；缺的先用本機替代，並在 `docs/DECISIONS.md` 記錄：

1. Neon 專案與連線字串（沒有就先用本機 docker compose 的 Postgres）
2. Google OAuth Client ID 與 Secret，以及允許登入的 email
3. GCP 專案、物件儲存 bucket、Cloud Run 與 Cloud Scheduler 權限（M0 只需準備好說明與腳本，不一定要實際部署）
4. Email 寄送方式（SMTP 或服務商 API），開發時用 console 輸出替代
5. GitHub 儲存庫

## 範圍

**範圍內**

- Monorepo 骨架與工具鏈（`web/`、`py/`、`db/`、`infra/`、`docs/`）
- 本機開發環境（docker compose、`.env.example`、Makefile）
- 資料庫遷移與 M0 所需資料表
- Python 共用層：設定、DB、`RawStore`、`Notifier`、交易日曆
- Provider adapter 框架（介面、註冊、主備援、重試與限速），只用假資料源驗證
- 排程任務框架（`job_runs`、冪等、檢查點）與兩個示範任務：`heartbeat`、`freshness_check`
- Next.js 外殼：mobile-first 版面、Auth.js 登入、全站路由保護、`/status` 資料狀態頁、`/admin` 佔位頁
- CI（GitHub Actions）與 ETL 容器映像
- 文件：README、部署說明、`docs/DECISIONS.md`

**範圍外（不要做）**

真實資料源串接、日線與財報擷取、15 年回填、持股功能、圖表、新聞、LLM、LINE 推播實作（只留介面）、Redis、FastAPI、篩選器與回測、Terraform。

## 任務

每個任務完成後跑對應檢查，並單獨提交。

### T1 儲存庫與工具鏈

- `web/`：Next.js（App Router、TypeScript strict）、Tailwind、shadcn/ui、TanStack Query、ESLint、Vitest，用 pnpm。
- `py/`：uv 專案，Python 3.12；ruff、型別檢查（mypy 或 pyright 擇一）、pytest。
- 根目錄：`Makefile`（指令見 `CLAUDE.md`）、`.gitignore`、`.editorconfig`、`README.md`。
- 驗收：`make py-test` 與 `make web-check` 在乾淨環境可通過（內容可以只有一個冒煙測試）。

### T2 本機環境

- `docker-compose.yml`：Postgres 16。
- `.env.example`：列出所有環境變數（資料庫、OAuth、白名單 email、RawStore 路徑或 bucket、Email 設定、服務間驗證密鑰預留），附說明。
- 驗收：`docker compose up -d && make migrate` 後資料庫可連線。

### T3 資料庫遷移與 schema

遷移放在 `db/migrations/`（SQL 為唯一來源，工具選 dbmate 或 Alembic 並在 DECISIONS 說明）。Web 端用型別產生器（例如 kysely-codegen）取得型別，不手寫。

M0 建立下列表（其餘表由各里程碑自己的遷移新增）：

| 表 | 重點欄位與規則 |
|---|---|
| `trading_calendar` | `date` 主鍵、`is_trading_day`、`note`；匯入官方休市表的工作留到 M1，M0 只建表與以週末判斷的暫時種子，並在程式裡標 TODO |
| `stocks` | `id`、`symbol`、`market`（上市、上櫃）、`type`（stock、etf）、`name`、`industry_code`、`listed_date`、`delisted_date`；唯一鍵（`symbol`、`listed_date`） |
| `prices_daily` | （`stock_id`、`trade_date`）唯一；原始 `open/high/low/close`、`volume`（股）、`turnover`；`adj_factor numeric(18,10)` 預設 1；`source`、`fetched_at` |
| `corporate_actions` | `stock_id`、`ex_date`、`action_type`（現金股利、股票股利、減資、分割等）、`cash_dividend`、`stock_dividend_ratio`、`ratio`、`pay_date`、`source` |
| `financial_item_map` | `industry_type`（general、bank、insurance、securities、holding）、`item_code`、`label_zh`、`statement`（IS、BS、CF）、`source_label`、`is_cumulative` |
| `financials` | 長表：`stock_id`、`period_end`、`period_type`（Q、Y）、`statement`、`item_code`、`value numeric`、`publish_date`（可空）、`revision int default 0`、`source`、`raw_object_id`；唯一鍵（`stock_id`、`period_end`、`statement`、`item_code`、`revision`） |
| `monthly_revenue` | `stock_id`、`revenue_month`、`revenue`、`publish_date`（可空）、`source` |
| `raw_objects` | `id`、`provider`、`dataset`、`params jsonb`、`uri`、`sha256`、`bytes`、`fetched_at`；以 `sha256` 去重 |
| `job_runs` | `id`、`job_name`、`params jsonb`、`status`（running、succeeded、failed、skipped）、`started_at`、`finished_at`、`rows_written`、`error`、`checkpoint jsonb`、`trigger`（schedule、manual） |
| `settings` | `key` 主鍵、`value jsonb`、`updated_at`（手續費折扣等個人設定之後放這裡） |
| `audit_log` | `id`、`at`、`actor`、`action`、`target`、`detail jsonb` |
| `watchlist` | `stock_id` 主鍵、`added_at`、`note` |
| `portfolio_transactions` | `id`、`stock_id`、`trade_date`、`side`（buy、sell）、`quantity`（股，正整數）、`price`、`fee`、`tax`、`note`；M2 才會使用，M0 只建表 |

規則：外鍵與索引要齊全；時間戳一律 `timestamptz`；金額與價格用 `numeric`，不用 float；遷移可重複在空資料庫上完整執行；每張表在遷移裡加簡短註解（`COMMENT ON`）。

驗收：空資料庫跑完遷移成功；有一個測試驗證關鍵唯一鍵與預設值（例如 `adj_factor` 預設 1、`quantity` 必為正）。

### T4 Python 共用層（`stockhub/common`）

- 設定：pydantic-settings，從環境變數讀取，缺必要設定時啟動即失敗並說清楚缺哪個。
- DB：SQLAlchemy 2 連線與 session 工具；小量 repository 輔助函式（upsert）。
- `RawStore` 介面與兩個實作：本機檔案系統、GCS。路徑規則 `raw/{provider}/{dataset}/{yyyy}/{mm}/{dd}/{sha256}.json.gz`；寫入同時登錄 `raw_objects`，相同 `sha256` 不重複存。
- `Notifier` 介面與實作：`ConsoleNotifier`（開發）、`EmailNotifier`（SMTP，依環境變數）；`LineNotifier` 只留介面與 `NotImplementedError`，M6 再做。
- 交易日曆：`is_trading_day(date)`、`previous_trading_day(date)`、`trading_days_between(a, b)`，資料取自 `trading_calendar`。
- 驗收：以上都有單元測試；`RawStore` 的重複寫入、`raw_objects` 登錄、交易日曆查詢都被測到。

### T5 Provider adapter 框架（`stockhub/etl/providers`）

- 抽象介面：`PriceProvider`、`FinancialProvider`、`QuoteProvider`（方法簽名先定最小集合：依日期區間取日線、依期別取財報、批次取即時報價）；回傳型別用 pydantic 模型，不回傳 DataFrame 當介面。
- Registry：由設定指定每個資料類型的主來源與備援順序。
- 呼叫包裝：重試加指數退避、每來源限速、主來源失敗自動切備援並記錄；所有原始回應經 `RawStore`。
- 只實作 `FakePriceProvider` 與 `FlakyFakeProvider`（可設定失敗率）供測試。
- 驗收：測試涵蓋主來源失敗切備援、全部失敗時拋出明確錯誤、限速與重試行為。

### T6 排程任務框架（`stockhub/etl`）

- `Job` 基底類別與 `run_job(name, params, trigger)`：開始時寫 `job_runs`（running），結束寫狀態、筆數、錯誤；重複執行同一參數不得產生重複資料；支援檢查點（`checkpoint jsonb`），可中斷續跑。
- CLI：`python -m stockhub.etl run <job> [--date YYYY-MM-DD] [--param k=v]`，`list` 列出所有任務。
- 示範任務：
  - `heartbeat`：寫一筆小型原始物件並更新 `job_runs`，用來驗證整條路徑。
  - `freshness_check`：檢查 `prices_daily` 最新日期是否落後上一個交易日，落後則經 `Notifier` 發 Email；同一任務連續失敗合併為一封（以 `job_runs` 判斷）。M0 資料表是空的，所以預期會判定為「落後」，測試用假資料驗證兩種結果。
- `infra/Dockerfile`（ETL 映像，多階段、非 root）與 `infra/README.md`：說明如何建置、以 Cloud Run Job 執行、以 Cloud Scheduler 排程；附可執行的 `gcloud` 指令範例，不做 Terraform。
- 驗收：本機 `make migrate && uv run python -m stockhub.etl run heartbeat` 成功並在 `job_runs` 看到紀錄；重跑不重複；任務中途失敗後續跑能接續。

### T7 Web 外殼

- 版面：mobile-first；手機底部導覽、桌機側邊欄。導覽項目先放：首頁、持股、個股、市場、篩選器、回測、狀態、設定（多數是「即將推出」佔位頁）。
- 設計 token：紅漲綠跌（漲跌色用語意 token，如 `--color-up`、`--color-down`，可切換）。
- 登入：Auth.js、Google OAuth；環境變數 `ALLOWED_EMAIL`（可逗號分隔多個）做白名單；不在名單的人登入後被拒絕並顯示說明。
- 保護：middleware 預設保護全部路由與 `/api/*`，只放行登入頁與 Auth.js 端點；另有測試驗證未登入存取會被擋。
- `/status`：列出最近的 `job_runs`（任務名、狀態、開始時間、耗時、筆數、錯誤摘要）與各資料集的最新日期（M0 只有 `prices_daily`，顯示為空也要正確）。以 Next.js route handler 或 server component 直接查資料庫。
- `/admin`：佔位頁，顯示「設定中心將隨里程碑建置」，並預留稽核紀錄的讀取函式。
- 驗收：手機寬度（375px）與桌機都可用；白名單內登入成功、白名單外被拒；`make web-check` 通過。

### T8 CI

- GitHub Actions：
  - web：安裝、lint、typecheck、test。
  - py：ruff、型別檢查、pytest（使用 Postgres service container，先跑遷移）。
  - 遷移檢查：空資料庫完整套用遷移。
- ETL 映像建置工作流程（只建置，推送與部署步驟寫成註解或手動觸發，等使用者提供 GCP 設定後再啟用）。
- Web 部署採 Vercel 的 Git 整合，在 README 說明設定步驟與需要的環境變數。
- 驗收：開 PR 時三項檢查都會跑並通過。

### T9 文件

- `README.md`：專案簡介、快速開始（本機）、環境變數表、部署步驟（Vercel、Neon、Cloud Run Job、Scheduler）、備份與還原測試的預定作法（M0 先寫文件，不實作）。
- `docs/DECISIONS.md`：記錄 M0 期間的所有選擇與偏離（遷移工具、型別檢查工具、假設等）。
- 更新 `CLAUDE.md` 的指令與慣例區，使其與實際一致。

## 完成定義

- 所有驗收項目通過，CI 為綠燈。
- 乾淨環境照 README 步驟能在 30 分鐘內跑起本機環境、套用遷移、執行 `heartbeat`、登入並看到 `/status`。

- `docs/DECISIONS.md` 記錄了所有偏離與待使用者確認的事項。
