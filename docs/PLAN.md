# 規劃摘要（v0.5，2026-10-20）

這是使用者與 Claude 規劃問答的濃縮版，完整版在使用者的 Claude 文件「台股分析平台 規劃書」。里程碑任務細節以 `docs/M0.md` 等任務檔為準。

## 1. 範圍與前提

| 項目 | 決定 |
|---|---|
| 使用者 | 個人自用，單人登入 |
| 標的 | 上市、上櫃、ETF（不含權證） |
| 歷史資料 | 盡可能回填 15 年以上 |
| 即時性 | 全市場盤後更新；持股與自選清單盤中每 30 秒 |
| 資料預算 | 免費為主，少量付費 API（FinMind）；之後可接券商 API |
| 回測嚴謹度 | 實用優先，先跑起來再補強 |
| 通知 | LINE（僅高重要度）+ Email + 站內 |
| LLM 預算 | 每月數百元新台幣，只處理重要新聞，用小模型 |
| 裝置 | 手機與桌機都要完整支援（mobile-first） |

功能：個股基本面、籌碼面、總經儀表板、大盤與國際市場、產業與題材熱力圖、新聞與公告摘要加情緒、PTT 社群情緒、持股追蹤與損益、K 線與技術指標（MA、KD、MACD、RSI）、選股篩選器與回測。

## 2. 架構

- ETL 與網站分離：Vercel 不跑長任務。
- 前端與一般查詢：Next.js route handlers 直接查資料庫。
- 篩選器與回測：Python API（FastAPI），非同步（提交、輪詢、取結果），不對外公開。
- 資料源轉接層：`PriceProvider`、`FinancialProvider`、`QuoteProvider`，每個來源一個 adapter，設主來源與備援。
- 技術指標：前端用日線資料計算；Python 端用同一套公式，兩端用共用測試資料驗證。

## 3. 資料來源

| 類別 | 來源 |
|---|---|
| 行情與籌碼 | 證交所、櫃買中心 OpenAPI |
| 大戶持股 | 集保戶股權分散表（每週） |
| 財報與公告 | 公開資訊觀測站（MOPS）、FinMind |
| 總經 | 國發會景氣燈號、中央銀行、主計總處、PMI、FRED |
| 國際市場 | yfinance、FinMind：S&P 500、Nasdaq、費城半導體、日經、KOSPI、美元兌台幣、美元指數、美債殖利率、VIX、黃金、原油 |
| 盤中報價 | 主來源：永豐 Shioaji（僅行情，不下單；等使用者開戶、申請 API Key）；目前使用證交所 MIS（D-056），之後當備援，另可加 twstock、yfinance、FinMind |
| 新聞 | Google News RSS、財經媒體 RSS、MOPS 重大訊息 |
| 社群 | PTT 股票板（Dcard 暫不做） |

twstock 與 yfinance 是非官方管道，可能被限流或改版，必須有備援與失敗告警。各來源條款與額度正式串接前要再確認。

Shioaji adapter 只實作 `QuoteProvider`，登入時只要 API Key 和 Secret，不載入下單憑證。Shioaji 的 session 約 24 小時過期，所以 adapter 啟動時要先檢查 session 和行情連線，過期或斷線就重新登入，並重試一次；重試後還是失敗，就交給 `ProviderRouter` 切換到備援。

FinMind MCP 只在開發與研究時使用：在 Claude Code 裡臨時查資料、驗證想法。正式擷取一律走 provider adapter 與 RawStore（規則 5、6）。

## 4. 資料模型重點

- 價格存原始價與還原因子；除權息、減資、分割記在 `corporate_actions`。
- `financials` 長表，含 `publish_date` 與 `revision`；另有科目對應表，按產業類型（一般、銀行、保險、證券、金控）定義指標。
- 已知陷阱：存活者偏差（保留下市日）、還原股價、財報時點（用公布日對齊）、2013 年前後會計準則斷層。
- 回測中財報條件以法定申報截止日當資料可用日（保守估計）。
- 題材：`themes`、`stock_themes`（多對多，含 `valid_from`、`valid_to`）。
- 預計算每日特徵寬表 `stock_features_daily`，供篩選器與回測。

## 5. 新聞、社群與警示

流程：抓取（RSS、MOPS、PTT）→ 去重（網址與標題相似度，再用向量嵌入合併同一事件）→ 關聯個股 → LLM 單次呼叫輸出 JSON（摘要、情緒、事件類型、重要度、涉及產業或題材）→ 分級警示。

- 關聯分兩層：直接提及、產業關聯（`relation_type` 與權重）；產業關聯新聞視同直接新聞可觸發警示，但需同事件合併、門檻略高、LINE 額度保護。
- LLM 漏斗：規則預篩（持股、自選、MOPS 重大訊息）、去重合併、小模型批次、結果快取、每日用量上限。
- 社群情緒是輔助指標，不當選股訊號。
- PTT 只抓 [標的] 分類，略過 [閒聊] 與 [新聞]；保留標題、推噓數、發文時間與原文連結，內文只在處理時使用，不存全文。
- PTT 情緒沿用新聞的 LLM 流程，不另外跑 CKIP 或 BERT 模型（Cloud Run Job 不裝 torch）。提示詞附一份台股與鄉民用語詞典（例如「反串」「丸子」「公園」），這份詞典在 `/admin` 維護。
- 每日情緒彙整：每檔股票每個交易日寫一筆情緒分數、文章數、推噓比，存進 `stock_features_daily`。累積足夠歷史後，就能回測「情緒極端是反向指標」這類假設。
- 只存摘要與原文連結，不存全文。

警示規則：

| 事件 | 判定 | 通道 |
|---|---|---|
| 持股或自選股的 MOPS 重大訊息 | 即時輪詢 | LINE + Email |
| 持股單日漲跌幅 | 超過近 20 日報酬標準差 k 倍（k=2.5），最低 3%，上限漲跌停 | LINE |
| 法人大幅買賣超持股 | 淨買賣超股數 ÷ 當日成交量，門檻約 10%，三大法人分開，加最低成交金額過濾；盤後 | LINE |
| 新聞情緒極端 | 分數極正或極負 | LINE |
| 總經事件 | 央行利率決策、景氣燈號變色 | LINE |
| 其他總經數據、PTT 熱度突增 | 輔助 | Email 彙整或站內 |

不設每日硬上限，只做同標的冷卻與同事件合併；追蹤當月 LINE 用量，接近額度時低優先事件降級為 Email 彙整。

資料擷取失敗或異常以 Email 通知，並做資料新鮮度檢查（例如傍晚仍未收到日線即告警）。

## 6. 介面

- 首頁由上到下：持股損益與今日漲跌、大盤與國際市場、重大新聞與警示清單、三大法人買賣超排行。
- 獨立頁面：產業與題材熱力圖（方塊=市值、顏色=漲跌幅）、總經儀表板與事件行事曆、個股頁、持股頁、篩選器、回測。
- 個股頁區塊順序：K 線與技術指標、基本面、估值、籌碼、新聞與社群情緒。
- 估值：本益比與股價淨值比河流圖、歷史殖利率、估值百分位（5 或 10 年，排除虧損期）、同業比較。
- 財報：單季化損益、現金流與自由現金流（營業現金流減資本支出）、杜邦分析（三因子）、規則式重大變化提示、月營收年增月增。
- `/admin` 設定中心：題材編輯、自選清單、警示規則、手續費設定、資料狀態、排程管理；隨里程碑逐步長出，手動操作寫稽核紀錄。
- 手機版：篩選器改分步驟表單、表格卡片化、K 線觸控縮放。

## 7. 持股與費用

單一帳戶，數量以「股」記錄；成本用平均成本法，除權息不調整總成本（現金股利另列收入，配股、分割、減資只改股數）；配息完全自動（股票與 ETF 都依交易所公布的金額與除權息前一交易日持股推算，標示估算值）；手續費用一次性設定檔（費率、折扣、最低收費、零股最低收費、當場折抵或事後退）；證交稅用固定稅率（股票 0.3%、ETF 0.1%，當沖減半、債券 ETF 免徵依法定期限）；融資融券與海外股暫不做。細節見 `docs/M2.md` 與 DECISIONS D-067 起。

## 8. 篩選器與回測

- 篩選：查詢 `stock_features_daily`，條件樹轉 SQL。條件涵蓋基本面、籌碼、技術、新聞與 PTT 情緒。情緒資料從 M6 上線日開始每天累積，所以情緒條件只能回測上線日之後的期間；回測期間早於上線日時，介面要標示。
- 回測：單一訊號策略與選股策略（條件組合加再平衡）共用引擎。再平衡頻率可自訂；權重可選等權重、市值加權、因子分數加權（單檔上限預設 10%）；基準可切換發行量加權股價報酬指數與 0050（還原價）；隔日開盤成交，含手續費、證交稅、滑價、漲跌停無法成交。
- 績效頁：年化報酬與波動度、夏普值、最大回撤與期間、換手率與成本侵蝕、超額報酬與 beta、年度與月度報酬表、持股明細與交易紀錄。
- 保存策略與每次回測結果；頁面固定標示「未含下市股、財報未做 point-in-time 對齊，績效可能偏高」。

## 9. 登入、安全、備份

- Auth.js、Google OAuth、單一 email 白名單；所有 API route 檢查 session；Python API 只收服務間請求。
- ETL 用獨立服務帳號；排程管理用權限受限的服務帳號。
- 備份：託管服務自動備份加定期 `pg_dump` 匯出到物件儲存（加密，保留近 30 天加每月一份）；完整備份涵蓋無法重建的表（持股、交易、題材、規則、設定、策略與回測結果）；上線前做還原測試。
